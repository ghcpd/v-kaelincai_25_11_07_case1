Description
This experiment evaluates AI models’ ability to implement, validate and harden an API change in a production flow. Canonical example: a commerce platform migrates inventory checks from /api/v1/checkStock to a region-aware /api/v2/stock/availability that requires additional params (regionId, warehouseGroup) and may return asynchronous/partial availability fields. The shopping cart service still calls the old API, causing incorrect availability, increased latency and wrong “out of stock” displays during peak promotions. The objective is to (1) reproduce the faulty behavior, (2) implement the updated API call and response handling, (3) add robustness for the new asynchronous fields, and (4) prove correctness and performance with automated tests and comparative metrics.
Key evaluation criteria
• Correctness and compatibility of both pre-change and post-change implementations.
• Proper handling of the new API schema (parameters, response shape, async fields).
• Backward compatibility strategies (graceful fallback, feature flagging, adapter patterns).
• Performance and latency impact (request duration, error rates).
• Robust test coverage for normal, boundary and malformed inputs.
• Reproducible environment and one-click execution producing a comparison report.

o	Include expected outputs for each test (HTTP status, parsed availability, fallback decision) and pass/fail rules.

d. Captures outputs, HTTP responses, internal logs, and timing.
e. Validates parsed results vs expected outputs and reports pass/fail per case.

o	Produce machine-readable results files: results_pre.json and results_post.json with per-case assertions, latencies, and error counts.

7.	Documentation / Explanation
